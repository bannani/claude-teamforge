# Playbook — brainstorm (Product Manager)

- Read before you ask: the README, the structure, the recent commits. Never ask the client what the project already answers.
- Establish four things: the problem and who has it, what success looks like, the constraints, what is out of scope.
- When there is a real choice, lay out two or three approaches with their trade-offs and say which one you recommend.
- Cut scope: the smallest version that solves the problem (YAGNI). Park the rest as "later".
- No code and no file in this phase. When the four things are clear or need the client, `teamforge phase questions`.
